# [1002] 查找共用字元 (Find Common Characters)

- **難度**：Easy
- **標籤**：`Array` `Hash Table` `String`
- **刷題日期**：2026-11-18
- **複習狀態**：🟢 修正局部統計歸零後 AC

---

## 1. 題目理解與邊界條件 (Input / Output / Constraints)
* **題目目標**：給定一個字串陣列 `words`，找出在 `words` 中**所有字串裡都出現過的字元**（包含重複出現的次數），並以單字元字串陣列（`vector<string>`）的形式回傳，回傳順序不限。
* **題目規格釐清**：
  - 若某個字元在所有字串中各自出現了 $c_0, c_1, \dots, c_{n-1}$ 次，則該字元在結果中必須重複輸出 $\min(c_0, c_1, \dots, c_{n-1})$ 次（例如在 `"bella"`、`"label"`、`"roller"` 中，`'l'` 分別出現 2、2、2 次，故輸出兩個 `"l"`）。
  - 回傳格式為 `vector<string>`（每個元素是長度為 1 的 `std::string`），而非 `vector<char>`。
* **輸入限制**：
  - $1 \le \text{words.length} \le 100$。
  - $1 \le \text{words}[i].\text{length} \le 100$。
  - `words[i]` 僅包含小寫英文字母（`'a'` 到 `'z'`）。
* **特殊狀況 (Edge Cases)**：
  - `words` 僅包含一個字串（`words.size() == 1`）：直接回傳該字串拆解出的所有字元。
  - 所有字串之間完全沒有任何交集字元：回傳空的 `vector<string>`（`{}`）。

---

## 2. 思路演進 (Intuition & Thought Process)

### 🟢 最佳化解法：雙固定陣列交集取最小值 (Direct-Address Table + Min Frequency)
* **核心思想**：由於字元範圍固定為 26 個連續小寫英文字母，可用長度為 26 的整數陣列作為直接定址表（Direct-Address Table / 輕量化 Hash Table）進行 $O(1)$ 查表統計。所有字串的「交集出現次數」，等價於**逐一比對每個字串的字元頻率並取最小值**。
* **演算法步驟**：
  1. **建立基準頻率表**：宣告長度為 26 的整數陣列 `count[26]`（全初始化為 `0`），先走訪第一個字串 `words[0]`，統計各字母出現次數作為初始最小頻率上限。
  2. **逐字串統計並取交集最小值**：
     - 從 `i = 1` 開始依序走訪後續每個字串 `words[i]`。
     - 為當前字串建立一個**全新的（全為 `0`）**局部頻率陣列 `count2[26]`，統計 `words[i]` 中各字母出現次數。
     - 走訪 26 個字母位置 `j`（`0` 到 `25`），更新 `count[j] = min(count[j], count2[j])`。若某字母未在當前字串出現，`count2[j]` 為 `0`，取最小值後會自動將 `count[j]` 歸零。
  3. **還原輸出結果**：走訪 `count` 陣列的 26 個位置，若 `count[i] > 0`，則將字元 `i + 'a'` 轉為長度為 1 的 `std::string`（`string(1, i + 'a')`），重複推入結果陣列 `count[i]` 次。

---

## 3. 複雜度分析 (Complexity Analysis)
* **時間複雜度**：$O(N \times L)$（即所有字串的總字元數） — 假設陣列中有 $N$ 個字串、平均長度為 $L$，需走訪全部字元一次進行統計，並在每輪結尾固定掃描 26 格陣列（$O(26N) = O(N)$），整體時間複雜度為線性於輸入總字元數。
* **空間複雜度**：$O(1)$ — 扣除回傳答案所需的輸出空間外，演算法本身僅使用兩個固定長度為 26 的整數陣列（`count` 與 `count2`），額外輔助空間為常數級別。

---

## 4. 易錯點與盲點總結 (Key Takeaways)
* **局部統計陣列 `count2[26]` 必須在每輪迴圈內重新初始化歸零**：切勿將 `int count2[26] = {0};` 宣告在外層 `for` 迴圈之外，否則上一輪字串的字元計數會殘留並持續累加，導致交集頻率高估誤判。
* **為何本題用 `int arr[26]` 優於 `std::unordered_map<char, int>`**：
  - 在資料結構定義上，`int arr[26]` 屬於**直接定址表（Direct-Address Table）**（可視為無雜湊碰撞、映射函數為 `ch - 'a'` 的特例雜湊表），在記憶體中連續配置且零雜湊計算開銷。
  - 在「取最小值」步驟中，固定 26 格陣列對於未出現的字母天然保有預設值 `0`，可直接用統一的 26 次迴圈完成歸零；若用 `unordered_map` 則需額外處理「舊 Key 在新字串中不存在」的缺失邊界，寫法較繁瑣且易出錯。
* **`char` 轉 `std::string` 寫法**：C++ 無法直接將 `char` 隱式轉型推入 `vector<string>`，需使用 `std::string` 的填滿建構子 `string(1, i + 'a')`（或直接 `result.emplace_back(1, i + 'a')`）建立單字元字串。
