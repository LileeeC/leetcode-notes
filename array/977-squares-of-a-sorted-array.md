# [0977] 有序陣列的平方 (Squares of a Sorted Array)

- **難度**：Easy
- **標籤**：`Array` `Two Pointers` `Sorting`
- **刷題日期**：2026-11-12
- **複習狀態**：🟢 一次 AC

---

## 1. 題目理解與邊界條件 (Input / Output / Constraints)
* **題目目標**：給定一個按**非遞減順序（已排序）**排列的整數陣列 `nums`，回傳每個數字平方後的新陣列，且結果也必須按非遞減順序排列。
* **輸入限制**：
  - $1 \le \text{nums.length} \le 10^4$（陣列非空，至少包含 1 個元素）。
  - $-10^4 \le \text{nums}[i] \le 10^4$（平方後最大值為 $10^8$，使用 `int` 不會發生溢位）。
* **特殊狀況 (Edge Cases)**：
  - 陣列包含負數、零與正數（負數平方後可能大於正數平方）。
  - 陣列全為負數（例如 `[-5, -3, -1]`）或全為正數（例如 `[1, 2, 3]`）。
  - 陣列長度為 1（例如 `[0]` 或 `[-4]`）。

---

## 2. 思路演進 (Intuition & Thought Process)

### 🔴 暴力法 (Brute Force: 平方後直接排序) - 初始想法
* **直覺**：遍歷陣列將所有元素平方，再呼叫 `std::sort` 重新排序。
* **複雜度**：Time $O(N \log N)$, Space $O(\log N)$。
* **瓶頸**：沒有利用到輸入陣列「原本就已經排序好」的特性，多花了排序的時間成本。

### 🟢 最佳化解法 (首尾雙指標 Two Pointers - 由大到小反向填充)
* **核心觀察**：由於原陣列已排序，負數越靠左絕對值越大、正數越靠右絕對值越大，因此所有元素平方後的數值分布呈現「**兩端大、中間小**」的趨勢。換言之，**當前剩餘元素中的最大平方值，必定出現在陣列的最左端 (`left`) 或最右端 (`right`)**。
* **演算法步驟**：
  1. 配置一個與 `nums` 等長的結果陣列 `result(n)`。
  2. 設定雙指標 `left = 0`、`right = n - 1` 分別指向原陣列首尾，並設定寫入指標 `pos = n - 1` 指向 `result` 的最後一格。
  3. 比較 `nums[left]^2` 與 `nums[right]^2`，將較大者填入 `result[pos]`，並將對應的端點指標向內移動一格（`left++` 或 `right--`），同時 `pos--`。
  4. 重複上述步驟直到 `left > right`。

---

## 3. 複雜度分析 (Complexity Analysis)
* **時間複雜度**：$O(N)$ — `left` 與 `right` 指標相向而行，整個陣列每個元素僅被存取與比較一次。
* **空間複雜度**：$O(N)$ — 需配置一個長度為 $N$ 的 `result` 陣列來儲存並回傳排序後的平方結果（若不計輸出陣列，額外輔助空間為 $O(1)$）。

---

## 4. 易錯點與盲點總結 (Key Takeaways)
* **「反向填充」取代「正向合併」**：若先用二分搜尋找 `0` 的分界點，再從中間向兩邊擴散由小到大填值，需要額外處理「其中一邊指標先走完」的邊界判斷；改用首尾雙指標**由大到小從尾巴往前填**，邏輯大幅簡化且無需特判邊界。
* **迴圈終止條件**：`while (left <= right)` 必須包含等號（`<=`），確保當最後剩下一個元素（`left == right`）時，該元素仍會被寫入 `result[0]`。
